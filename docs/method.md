# 手法（最終版）と設計判断

## 問題設定

- 入力: 無線機から取り出した 1 フレーム（20 ms）あたり S ビットの列です。インターリーブ済みで、どのビットが何を
  表すかは分かりません。本リポジトリでは `neurodec/blackbox/` が「無線機」を模擬し、エンコーダー CLI の出力に秘密の置換
  （フレーム内＋2 フレームのバーストをまたぐ）をかけてから学習側に渡します。
- 教師: 送信したクリーン音声（8 kHz）です。エンコーダーに入るのは部屋・スピーカー・AGC・雑音を模擬した音声です。
- 制約: 録音 12 時間以内、無線遅延は一定（1 回だけプール推定）、コーデック知識ゼロ。
- 評価: 未知話者の PESQ-NB / STOI / log-mel 誤差 / F0 RMSE / V-UV 誤り、clean と音響シミュ、BER 0 / 1 / 3 %、
  性別別。同一発話の WAV（target / コーデック自身のデコーダー / 提案）で試聴します。

## 論文手法（出発点）と限界

Kim et al. 2022: ビット軸 5 幅の 2D CNN ＋ フレーム内ビット attention ＋ FFN（dequantization network、
2.5M）→ 56 次元条件 → Parallel WaveGAN。再現は `neurodec/models/dequant.py`, `pwg.py`、設定は
`configs/experiments/ja_check*.yaml` です。限界は (a) ビットの隣接性を仮定する（インターリーブで崩れる）、
(b) 時間文脈が ±6 フレーム、(c) PWG は学習が遅く、1 時間データでは PESQ 1.9 台で頭打ち、の 3 点です。

## 最終手法の構成要素

### 1. BitToken フロントエンド（`neurodec/models/frontends.py`）

ビット位置 s の値 b を埋め込み E[s, b] に写し、フレーム内で結合 → MLP（1536）→ 幅 384 のフレームベクトル →
バースト内位置（frame index mod block_frames、公開情報）の埋め込みを加算 → 時間方向 ConvNeXt 1D 8 ブロック
（kernel 7）→ 56 次元条件 ＋ 補助ヘッド（log-mel 80、log-F0、有声度、5 帯域非周期性）。
位置埋め込みが順序を吸収するので `bit_order` に依存しません。論文 frontend に対し mel 回帰 probe で
−1.2 dB、同 step の本学習で PESQ +0.25（両バックエンド、`results/joint_controls_20k`）でした。幅 384 / 8 ブロック
（7.8M）は幅 256 / 6（3M）より +0.15 です。

### 2. クリーン音声だけで学習するボコーダー（`neurodec/models/istft.py`）

mel 条件付き小型 iSTFT 生成器（n_fft 512、hop 80、幅 192、ConvNeXt 6 ブロック、学習型アップサンプラ、
1.5M）＋ MPD（周期 2,3,5,7,11）/ MRD（FFT 256/512/1024）識別器で、損失は MR-STFT ＋ mel L1 ＋ LSGAN ＋
feature matching です。`--frontend mel` で学習し、録音データもコーデック知識も使いません。
正解 mel からの再合成は PESQ 3.68〜3.70 / STOI 0.96（`results/mel_istft_*_job`）、推論は 12 秒分を 2.6 ms で処理します。

### 3. mel ブリッジと凍結ボコーダー（`model.mel_bridge`, `train.freeze_backend`）

フロントエンドの予測 log-mel を、事前学習ボコーダーの入力射影（ブリッジ）に通します。ボコーダーは凍結し、
波形損失・mel 損失・補助 mel 損失・敵対的損失はすべてフロントエンドに流れます。共同微調整（全体を更新）と
全指標で同等（`results/joint_b49_wide_bridge_job`）なので、新コーデックではフロントエンドだけを学習すればよいです。
出荷時は 1 つのチェックポイントにまとまります（probe と組み合わせる場合は `scripts/assemble_decoder.py`）。

### 4. 周期性の補助ヘッド（`model.f0_head`, `model.ap_bands`, `loss.lambda_f0 / lambda_vuv`）

教師は学習データのクリーン音声から `scripts/precompute_f0.py` で自動抽出します（pyworld dio+stonemask の F0、
倍音位置と倍音間のエネルギー比から求めた 5 帯域の非周期性）。フロントエンドに log-F0 L1 と有声度 BCE、
帯域非周期性 BCE を加えます。効果は全条件で +0.05〜0.1（2.48 → 2.54 → 2.59）です。補助タスクとしての効果で、
ボコーダーへの励振入力としては使われていません（下記）。

### 5. ビット誤り拡張（`train.ber_max: 0.02`）

学習時に入力ビットをランダムに 0〜2 % 反転します。BER 1〜3 % で受信機を大きく上回る頑健性の源で、clean 品質は落ちません。

### 6. 学習手順（`scripts/new_codec_pipeline.py` が生成するキュー）

1. `neurodec.data.build`: キャンペーン生成（PTT 60 秒セッション、音響シミュ、一定遅延の推定、clean / sim テスト）。
2. `scripts.precompute_f0`: F0・有声度・帯域非周期性の教師。
3. `scripts.probe_frontend`（20000 step）: ビット → log-mel の回帰でフロントエンドだけを学習します。
   数分で「フロントエンド単体の性能計」が得られ、本学習の初期値になります。
4. `scripts.run_stage`（30000 step）: probe のフロントエンド ＋ 凍結ボコーダー（＋その識別器）で本学習し、
   終了後に自動評価（clean / sim × BER）します。
5. `scripts.listen_lang`: 性別別の試聴セット（target / コーデック自身 / 提案）。

### 推論経路

ビット列 → frontend → 予測 log-mel（＋F0 ヘッド）→ ブリッジ → ボコーダー → 8 kHz 波形。
`neurodec.infer` は 500 フレームずつ文脈付きで復号します。チェックポイントの meta には blackbox 節を含めません。

## 設計判断の根拠（短縮版、詳細は experiments.md）

- ボコーダーは律速ではありません（上限 3.70 対 受信ビット条件 2.59）。残る差はビット → mel のフロントエンド誤差です。
- データ量は 3〜6 時間で飽和します（1/3/6/12 h: 2.12 / 2.26 / 2.37 / 2.33）。構造側（幅、補助目標、BER 拡張）が効きます。
- 励振（正弦波・cyclic noise・帯域別・Wavehax 型）を「特徴として足す」とボコーダーは完全に無視します
  （F0 を 0.8 倍や 0 にしても PESQ が変わりません）。構成で強制するソースフィルタ方式は男女差を消しますが品質上限を
  3.26 に下げます。最終版は励振入力を持つボコーダーで学習しましたが、機能的には励振なしと同じです。
- 男性話者は受信機の方が PESQ で 0.3 高いです（2.56 対 2.86）。この差はボコーダー上限にも存在し（3.57 対 3.86）、
  ピッチ精度・事前学習データの男女比・hop・バックエンド種別では説明できませんでした。試聴では男女ともに実用的です。

## 既知の限界

- 8 kHz 狭帯域前提（PESQ-NB）です。
- clean 条件の PESQ はコーデック自身のデコーダーに 0.2 届きません。男性の声でより顕著です。
- インターリーバーは「フレーム内＋2 フレームのバースト」を想定しています。より長い周期のインターリーブはバースト長
  （`blackbox.block_frames`、公開情報として扱う）を合わせる必要があります。
- FEC 込みの 72 bit（`bits72`）は論文再現期にのみ試しました。
